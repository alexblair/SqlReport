# 交付物模板（三件套，字段是硬性的）

> 本文件是 `ai-retro-lean-iteration` 的支撑件。三条产出**同时**交付，缺一条视为未完成。
> 所有字段都必须填满；**没有实测证据的条目一律删掉，不许留占位句**。

## 交付物 ① AI 表现复盘 · 问题清单

按下面**五类**分组（没有该类问题的类别写「本次范围内未出现」，不要编）。每条必须带位置与数值。

| 类别 | 判据 | 典型历史现象 |
|------|------|--------------|
| 任务执行效率 | 推理路径迂回、反复校验、重复调用工具、不必要的多轮询问 | 同工具同参数重复调用；同一文件反复整读；可行步骤却先问再问 |
| 无意义行为 | 冗余寒暄、前置铺垫、无效解释、多余的总结复述 | 复述用户已给的需求；回答末尾重复结论；「我先说明一下」式铺垫 |
| 垃圾行为 | 偏离任务的发散输出、额外自发追问、脱离指令的自行拓展 | 顺手改了范围外的东西；自发加做用户没要的检查 |
| 负面行为 | 拒绝合理任务、错误的角色偏移、越界应答 | 把可做的任务推回用户；越权裁决冲突依据 |
| 低效率行为 | 过长的内部思考、拆分不必要多步骤、重复解析相同知识库片段 | 一步只发一个互不依赖的调用（单调用步占比高）；重复解压/重复读同一片段 |

条目模板（**每条一行，字段顺序固定**）：

```
[类别] 现象一句话 —— 位置：<会话id 前缀·第N步> —— 实测：<数值，来自 session_cost.py> —— 影响：<重发成本/步数/返工>
```

**位置与数值缺一不可**：写不出「第几步 + 实测值」的条目 = 印象，删掉（或先去取证）。

## 交付物 ② 针对性轻量化优化变更清单

**分工必须清楚**（四类，逐条归类；一条变更只归一类）：

1. **规则 & 行为规范修改项**（`AGENTS.md` 硬约束、`MEMORY.md`、知识库流程分卷）
2. **MCP & 工具联动逻辑调整项**（触发器、调用前置条件、阈值、命令封装）
3. **知识库梳理重构项**（分卷裁剪/合并/搬迁，只动结构与归属，不重写内容）
4. **顶层提示词约束增补项**（`AGENTS.md` 入口/路由/最小集、技能正文、脚本内置提示）

每条按**四栏**写，**四栏缺一不可**：

| 栏位 | 要求 |
|------|------|
| 现存原始内容 | 引用**原文**（带文件路径 + 行号或小节名）；没有原文 = 新增项，写「无（新增）」 |
| 识别出的历史问题 | 指向交付物 ① 的条目（同编号） |
| 本次拟修改内容 | **最小改动**：增补 / 裁剪 / 局部修正 / 加边界约束 / 删无效引导句 / 调整触发条件（六选一并写明） |
| 修改后预期收益 | 量化方向：省多少 token / 减几步 / 规避哪一类不良行为（说不出量化方向 = 这条不该做） |

**改动级别六选一（必须写明）**：`增补`｜`裁剪`｜`局部修正`｜`加边界约束`｜`删无效引导句`｜`调整触发条件`。

## 交付物 ③ 效果预判与风险

分两节：

**效果预判**（每条都指向具体机制，不许写「会更好」）：

- TOKEN 缩减方向：削减哪一处的**重发成本**（新增 × 剩余步数），预计量级
- 会话步骤缩短：消除哪类重复调用/多轮询问，预计步数
- 无效动作减少：封死哪一类行为（对应交付物 ② 的哪条）

**风险点与防范**（每条风险必须配一条防范措施）：

| 风险类型 | 自问 | 防范 |
|----------|------|------|
| 质量下降 | 这条约束会不会让代理漏读关键文件/漏做验证？ | 保留哪条兜底判据 |
| 过拟合 | 是不是只为某一个会话的个例加的规则？ | 该规则是否至少回溯 2 处独立现象 |
| 冲突 | 与现有硬约束/spec 是否矛盾？ | 按「当次指示 > `AGENTS.md` > 最新生效 spec > 旧 spec/plan」裁决并记入 |
| 反向成本 | 新增的规则/工具本身会不会增加每步固定地板？ | 净收益必须 > 0，否则不做 |

## 落地记录（随交付物一起给）

- 报告落 `docs/compose/reports/YYYY-MM-DD-<主题>.md`（结论 + 数值 + 复现命令）
- 改动只落在**被授权的最小范围**内；纯新增/纯文档改动无需 codegraph sync，动了 `.py`/`.js` 则同任务内 sync（硬性 #19）
- 用一句话回报「改了什么 / 实测数值 / 未做什么」，不许写「应该已修复」
