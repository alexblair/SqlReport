# AI 运行表现复盘 · 轻量化迭代

**核心原则**：复盘产出的每一条优化点，都必须能写成「会话 · 步 + 实测数值」；
**改动越小越好，质量不降是前提**。

## 三条铁律（违反即返工）

1. **范围未确认不动手**（见 §0）。**用户的措辞不构成范围**——「前面几段会话」「最近那些」「你看着定」都不是范围。
2. **只做最小改动**。禁止重写整套规则 / MCP / 知识库；每条改动必须六选一：
   `增补`｜`裁剪`｜`局部修正`｜`加边界约束`｜`删无效引导句`｜`调整触发条件`。
3. **一切优化点溯源到真实证据**。写不出「会话 · 步 + 实测值」的条目 = 印象，删掉。

## §0 确认范围（硬门禁，先做这一步）

用一次 `ask_user_question` 问：会话 ID 集合 / 时间区间 / 业务场景范围。
问题里**必须带候选**（至少 id 前缀 + 标题；`--list` 给不出的字段就不写，改为在交付物 ② 里提「工具缺字段」），让用户勾选或自填。

- **允许**：`session_cost.py --list` 跑**一次**，只为生成候选项。
- **禁止**：拿到答复前跑 `--session` / `--last` / `--all`、解压或读 transcript、写任何问题清单。
- 用户答「你定 / 随便」→ 把候选**收窄成 2–3 个选项再问一次**（这是提问，不是自行拍板）；仍不答就列出候选项并停下。

> 为什么这么严：范围选错 = 全部取证作废重跑；而侦查阶段塞进历史的每一段内容，
> 都会被后面每一步重发（重发成本 = 新增 × 剩余步数）。**1 次提问 ≪ 1 轮返工。**

## §1 取证（只读，复用现成工具）

见 `references/evidence-and-metrics.md`：数据源、命令表、指标口径、陷阱。

- 首选 `venv/bin/python scripts/agent/session_cost.py`——它已输出「最贵步 · 重发成本 / 工具返回体积 / 重复调用 / 单调用步占比 / 预算违规项」。
- 开工前先看 `docs/compose/reports/` 最近 2 份报告：**已有结论的不重复分析**。
- 工具缺字段 → 写成「工具改动建议」（交付物 ②）；**不得现场自建统计脚本**（禁重复造轮子）。
- 复盘自身也受 token 纪律约束：> 60 步或上下文 > 120k 要落盘交接（结论 + 数值 + 复现命令落 `docs/compose/reports/`）。

## §2 归类：五类缺陷

| 类别 | 判据 |
|------|------|
| 任务执行效率 | 推理迂回、反复校验、重复调用工具、不必要的多轮询问 |
| 无意义行为 | 冗余寒暄、前置铺垫、无效解释、多余的总结复述 |
| 垃圾行为 | 偏离任务的发散输出、额外自发追问、脱离指令的自行拓展 |
| 负面行为 | 拒绝合理任务、角色偏移、越界应答 |
| 低效率行为 | 过长的内部思考、拆分不必要多步骤、重复解析相同知识库片段 |

## §3–§4 变更清单与三份交付物

**三份同时交付，字段是硬性的**：①问题清单 ②轻量化变更清单（四栏：现存原始内容 / 历史问题 / 拟修改内容 / 预期收益，并按「规则&行为规范 · MCP&工具联动 · 知识库 · 顶层提示词」四类分工）③效果预判与风险。
模板见 `references/deliverable-templates.md`，逐栏照着填。

## §5 落地与验收

1. 只改 `.md` → 无需 codegraph sync；动了 `.py`/`.js` → 同任务内 `codegraph sync`。
2. 知识库改动同任务内同步；报告落 `docs/compose/reports/YYYY-MM-DD-<主题>.md`。
3. 收尾 `venv/bin/python scripts/agent/cleanup_tmp.py --apply`；回报「改了什么 / 实测数值 / 未做什么」，禁写「应该是」。

## 反合理化表

| 借口 | 现实 |
|------|------|
| 「用户说『你看着定』= 授权我自己定范围」 | 那是把裁决权推回给你，不是给了范围。收窄成 2–3 个候选再问一次。 |
| 「标题一看就知道是哪几个会话」 | 候选 ≠ 范围。确认只花 1 次调用；跑错范围要重跑全部取证。 |
| 「先跑数据再问，效率更高」 | 确认前的取证可能全部作废；而且它会被后续每步重发。 |
| 「规则太散了，不如整章重写」 | 重写 = 引入未验证的新行为，违反质量优先。逐条改，一条一收益。 |
| 「这问题很典型，不用查会话我也知道」 | 记忆不是证据。写不出位置的条目一律删。 |
| 「工具缺字段，我自己写个解析脚本更快」 | 破坏单一实现来源。记为工具改动建议，不现场造。 |
| 「复盘求快，四栏就省两栏」 | 缺栏的变更清单不可验收 = 没做。 |

## Red flags —— 出现即停手

- 正准备在用户答复范围前跑 `--session` / `--last` / `--all`
- 心里在想「默认取最近 N 个会话」
- 正在 grep / 直接读 transcript 原文（应当先用 `session_cost.py`）
- 交付物 ② 有行缺「现存原始内容」或缺「预期收益」
- 打算一次改 3 个以上模块，或重写整份分卷 / 整份提示词

## 何时不用

- 用户只要一次性的结论、明确不要改动 → 只做 §1+§2，不要输出变更清单
