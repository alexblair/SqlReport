确认稿 v2 · 执行失败时的「错误引导」
目标：用户看到的不是一条技术报错，而是「发生了什么 + 可能是哪类原因 + 怎么解决 + 一键去修」。 所有执行失败都会带【编辑】入口，点击新开窗进入报表 #17「处置商管理一览表」的编辑页。 引导文案由一张字典驱动（见下方表格），后续新增错误类型只加词条，不再散落 if-else。

请选择版式

文案结构固定为三段，任何错误类型都套同一张皮：
查询执行失败：<发生了什么> / 可能原因：<什么情况会导致它> / 如何解决：<具体下一步>，最后是可折叠的原始错误。

写操作被拦截（报表 17 的真实场景）

方案 A2（推荐）：文案里的【编辑】可点，右侧另有「编辑报表」按钮

查询执行失败：该报表包含写操作语句且未开启『允许执行写操作』
可能原因：系统判定该报表 SQL 含写语句（INSERT/UPDATE/DELETE/DDL 等），而报表配置里没有勾选「允许执行写操作」。
如何解决：先确认这条 SQL 是否确实要写库。确实要写，勾选「允许执行写操作」并保存；如果它只是查询，说明写判定可能有误，请联系管理员复核。 需要修正这条报表时，点击 【编辑】 打开该报表的编辑页（新窗口），改完保存后回到本页重新执行即可。
