# 全站视觉体系 v2「石墨·鸢尾」设计（UI v2）

> 确认稿（用户已确认）：`docs/compose/spec/ui-v2-draft/index.html` ＋ 13 页 `preview-*.html` ＋ 报表配置页 `preview-reports-v2.html`（方案 A）。
> 令牌与对比度工具：`scripts/ui-v2/tokens.py`；确认稿生成器：`scripts/ui-v2/make_preview.py`、`make_reports_page.py`。
> 用户裁定：2026-09-30 选定**报表配置页方案 A（分组卡 + 层级导轨）**；同轮受理并修复合计的 4 条反馈（SQL 代码面隐形文字、快筛联动缺失、名称列竖排 + 表头不一致、父子层级丢失）。

## 1. 问题（为什么前几轮「改了 N 次还是丑」）

不是某一页没设计好，而是**全站没有统一尺度**。旧共享 CSS 实测：

| 指标 | 旧值 | 后果 |
|---|---|---|
| 十六进制色值 | 49 种（slate/indigo/emerald/amber/red 五套混用） | 无主色，页面之间「各灰各的」 |
| font-size 声明 | 76 处 / 12 种取值 | 无字阶，层级靠临场调 |
| padding 简写 | 74 处 / 37 种 | 无间距栅格，元素对不齐 |
| 圆角 / 阴影 / 行高 / transition | 12 / 12 / 7 / 14 种 | 同类组件形态不一致 |
| 内联 `style="…"` | 269 处 | 页面级 CSS 永远改不动；清理时还会丢语义 |

并且本轮暴露了三类**结构性**缺陷（都由「只改全局样式」造成）：

1. **class 撞名**：`.sql-head` 在生产是「SQL 列表头」标记，被复用成「代码工具条」→ 表头变怪。
2. **语义靠内联样式承载**：列宽 `style="width:…"`、父子层级 `margin-left/border-left`、配色 `style="color:#4f46e5"`——清理内联样式即丢失这些语义。
3. **多 class 各写一半**：`<pre class="sql-debug code-block">` 命中 `.code-block{深色字}` + `.sql-debug{深底色}` → 正文 **1.02:1（隐形）**。

## 2. 设计目标（验收口径）

1. **一把尺子**：颜色 / 字号 / 间距 / 圆角 / 阴影 / 动效全部取自令牌，页面级与内联样式一律不得再出现表现性声明。
2. **可验证的美观**：所有正文文字对有效背景对比度 ≥ 4.5:1（程序化审计，纳入测试门禁）。
3. **零横向溢出**：1280 / 1440 / 1920 三档下 `scrollWidth == clientWidth`。
4. **层级可读**：多级分类在右侧内容区有明确层级表达（导轨 + 缩进 + 字号下沉 + 深度色点），且不破坏表格/卡片对齐。
5. **功能零丢失**：URL 参数、表单协议、筛选/排序/导出/分页语义、路由与鉴权一律不动。

**硬性规则**：代码面的 `background` 与 `color` 必须**成对声明在同一条规则里**，禁止分属两个 class（历史事故根因，见 §1.3）。

### 3.3 字阶 / 间距 / 圆角 / 阴影 / 动效

- 字阶（px/行高）：11/16、12/18、13/20、14/22、16/24、18/26、22/30、28/36；正文字体栈含 PingFang SC / HarmonyOS Sans SC / MiSans / 思源黑体回退。
- 间距：4px 栅格（4/8/12/16/20/24/32/40）。
- 圆角：`--r-xs 4` / `--r-sm 6`（控件）/ `--r-md 10`（卡片）/ `--r-lg 14`（对话框）/ `--r-full`。
- 阴影：`--sh-1` 微浮起、`--sh-2` 浮层、`--sh-3` 抽屉/对话框；卡片默认**无阴影**，靠 1px 描边分层。
- 动效：120ms / 180ms，`cubic-bezier(.2,.8,.2,1)`；尊重 `prefers-reduced-motion`。

## 4. 组件口径（要点）

- **表格**：`th` 统一 12px / 行高 18px / 高 38px / `--ink-2`；粘性表头；`td` padding 9×12；数字右对齐 + `tabular-nums`；空态白底。
- **列宽体系（新增，替代内联 width）**：宽表用 `table.table-fixed` + `<colgroup>`（`col.c-check/c-name/c-sql/c-cfg/c-pool/c-memo/c-path/c-api/c-ops`）；无 colgroup 的表保留「第 2 列 ≥156px」兜底，避免名称竖排。
- **代码面 / SQL 高亮**：`pre`、`.code-block`、`.sql-debug`、`.sql-preview` 共用一个成对声明；词法类 `.sql-hl-keyword|string|number|comment|function` 用 §3.2 值。
- **快筛行 `.qf-row`**：`td` 用 `--bg-subtle`；「操作符 select（74–96px）+ 值 input（64–150px，聚焦放宽到 220px）」成组；联动契约沿用 `toggleFilterInput(inputName, select)`（`nofilter/isempty/notempty` → 隐藏 + disabled）。
- **分组卡与层级（报表配置页方案 A）**：`.cat-block`（卡）+ `.cat-head`（卡头：折叠钮 / 深度色点 / 名称 / 计数 / hover 出操作）+ `.cat-body`（列表行 `.rpt-row`）+ `.cat-cards`（卡片形态，`.rpt-card`/`.rc-*`）+ `.cat-children`（子级容器：1px 竖导轨 + 节点横线 + 逐级缩进；三级用浅色深度点，导轨同色不「断」）。
- **双视图**：每个分类**同数据各渲一份**（列表 + 卡片，对齐生产 `.view-list`/`.view-card` 语义）；勾选按 value 镜像（等价 `pickedReportIds()`），批量计数不翻倍。
- **登录页**：左品牌深色区（径向光晕 + 深底渐变）+ 右表单列；输入 38px、主按钮 38px。
- **禁止项**：新增页面级 `<style>` 补丁；表现性内联样式；新 hex（除令牌区）；emoji 图标；单 class 只管一半的底色/文字色拆分。

## 5. 实施要点（与硬性约束一致）

1. 公共层：`render._BASE_CSS` / `_COMMON_CSS` 换装为 v2；vendor hash 仍为 `sha256(CSS+"\n;;;\n"+JS)` 前 8 位（改 CSS 必须重算，勿断言具体 hash）。
2. 页面级补丁全部删除：`report.py _CSS`、`config.py _CONFIG_EXTRA_CSS`（含 `_REPORTS_EXTRA_CSS`）、`server.py` 登录页内联样式；必要规则收进公共层（含 `.qf-row`、`.sql-*`、`.debug-*`、`.rpt-*`、`#sec-reports` 作用域规则）。
3. 内联样式清理：只保留行为性声明（`display`/`visibility`）；被内联承载的语义改由 class 承担（列宽 → `colgroup`；层级 → `.cat-children`；配色 → 语义 class）。
4. 测试对齐：钉住旧 CSS 字面量 / 旧内联样式 / 旧 class 计数的断言按新口径改写；新增对比度门禁用例。
5. 文档：本 spec + `knowledge/06-ui-interactions.md` + `INDEX.md` 同步；最终对比截图留档。

## 6. 非目标

- 不改路由、鉴权、URL 参数、表单协议、缓存/调度语义。
- 不改报表数据页的功能行为（筛选/排序/分页/导出/结果集切换协议不变）。
- 不引入前端框架、构建链或外部字体（技术选型锁定：纯标准库 + 服务端 HTML）。
