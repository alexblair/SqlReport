0. 你反馈的两条 —— 已定位根因并修复

① SQL 代码面：文字与底色打架（正文隐形）

根因不是「配色不好看」，是两个 class 各写一半：pre.sql-debug.code-block 命中 .code-block{color:深墨}（给浅底用的）与 .sql-debug{background:深底}， 于是 深字压深底。实测旧稿正文对比度 1.02:1（等于隐形），只有高亮关键字还看得见—— 所以你看到的是「只剩 SELECT / FROM 几个词，字段全不见了」。旧 token 色也是给浅底配的（关键字 3.26:1 / 函数 3.60:1）。

改法：把代码面做成一个组件，底色与文字色成对声明、不许分开；重建 8 个词法色并逐个实算对比度。

② 快筛：选了操作符却没有值输入框

联动函数 toggleFilterInput() 定义在生产外链 common.js 里，而确认稿为了自包含把外链 JS 摘掉了， 于是 onchange 找不到函数——不是设计漏了，是确认稿少了这段交互。生产页面本身有这个输入框（默认隐藏）。

改法：按生产同一契约把联动补进确认稿（nofilter/isempty/notempty → 隐藏并禁用；其余 → 显示并启用）， 并把「操作符 + 值」做成一组紧凑控件（操作符 74–96px，值输入框 64–150px，聚焦临时放宽到 220px，失焦收回，避免把列撑开）。

方案 A · 分组卡 + 层级导轨（推荐）

  • 一级分类 = 卡片，卡头含折叠钮、深度色点、分类名、报表数、hover 才出的分类操作
  • 子分类 = 卡内「层级导轨」：竖向 1px 导轨 + 节点横线 + 逐级缩进 22px + 字号逐级下沉 + 深度色点（三级用浅色点）
  • 每行报表改为行卡片：名称 + 状态 chip + 配置 chips（分页 / 缓存优先 / 保活 / 写护栏）+ 连接池 + SQL 摘要 + hover 出操作
  • 把原来「默认分页 / 缓存 / TTL」三列并成一列 chips → 10 列变 5 个信息区，彻底消除挤压
  • 1280 / 1440 / 1920 三档零横向滚动

方案 B · 单表 + 分类路径列

  • 全部报表一张表，用「分类路径」列表达归属（经营分析 / 区域销售）
  • 列数 10 → 8（同样把三列配置并成 chips）；colgroup 固定列宽，表头统一
  • 跨分类排序、批量操作天然一致；代价是失去分组卡的视觉分区
  • 适合「按属性筛选 + 跨分类比较」的用法；如果你更常按分类逐块管理，A 更顺手

5. 请你确认这几点

  • 整体方向：明亮工作台 + 深色侧栏、单一鸢尾强调色、克制的边框与阴影。若你想要别的气质（例如整站深色、或更暖的纸感浅色），确认稿底部可一键换色调，也可以直接说，我换方向重出。
  • 登录页：左侧深色品牌区 + 右侧表单的分栏。若你更想要「居中单卡」，改回成本很低。
  • 信息密度：表格行高 40px、单元格 padding 9×12、正文 13px。想更紧凑（行高 36）或更宽松（行高 44）都可以，我按你的选择一次调到位。
  • 快筛行：保留但降噪（我们现在这样）。也可以收进「高级筛选」抽屉，表格更干净但少一个高频入口——你定。
  • 侧栏宽度：248px（比现在 240px 略宽）。可以按你屏幕调整。
