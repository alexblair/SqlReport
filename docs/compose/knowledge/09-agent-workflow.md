# 多代理协作 · 执行效率与取证纪律

> 对应硬性约束 #13–#16。**仅在派发子代理、或需要严格取证纪律时才需读本卷**；
> 日常单会话开发只需 AGENTS.md 的硬约束条目与本卷标题下的「一句话版」。

## 何时读本卷

| 场景 | 读哪节 |
|------|--------|
| 要 spawn / wait / cancel 子代理 | 「派发纪律」+「预算与监控」+「简报五件套」 |
| 只是自己写代码、跑测试 | 「执行效率与取证纪律」一节即可 |
| 任务卡住、同一问题反复失败 | 「两败必停」在 `08-testing-conventions.md` |

## 一句话版

- 同任务**全局至多一个活跃子代理**；派前查状态、中断不重发、cancel 不算数。
- >30s 的任务后台落盘 + 带退出判据的轮询，**禁止整段前台 sleep**。
- 测试结果**落盘再取数**（同一动作完成两件事）。
- 改文件走**编辑三拍**：Read 定位 → `old_string` 逐字复制 → Edit。
- 收尾必报：进度表 + 【任务完成】+ 简报。

## 派发纪律（硬性 #13）

适用：任何「派子代理干活 + 主会话验证收口」的多步任务。以下每条都对应本项目实际发生过的事故。

1. **派发前盘点**：`Task list` + 该任务 `Actor status`——已有活跃代理就等待或发消息续用，**禁止再 spawn 一个**。同任务多代理并发 = 写入竞态（曾出现：同一函数被两方改出 `force/always` 参数名冲突、`.grid-3` CSS 重复定义、一方覆盖另一方半成品）。
2. **一条消息只发一个 spawn**；spawn 成功后立刻把 actor_id 记入任务条目（Task 的 event_summary 或特性文档），断线恢复时以它为准判断「已派/未派」。
3. **中断≠失败**：工具调用（spawn/wait/Question/bash）被中断后，禁止原样重发——先 `status` 查清上一动作是否已生效，再决定续、换或撤。
4. **重派前置**：cancel → `status` 确认 idle/completed → `stat` 目标文件 mtime 前后一致（无残留写入）→ 才允许重新 spawn。cancel 回执与「已取消」通知都可能与实际执行状态不一致。
5. **Brief 复用**：通用协议（禁 rm、venv、中文、两败必停、测试命令模板）写在本卷与特性文档里，子代理 brief **只写增量**（任务范围、页面清单、验收），不整段重贴。

### 简报五件套（每次 spawn 必含，缺一即缺陷）

避免子代理从零摸索（曾浪费 20%+ token 且产生认知偏差）：

1. **必读顺序**：根 `AGENTS.md` 与 `knowledge/INDEX.md` **通读**；任务相关分卷与特性文档**只读涉及章节**（按标题跳读，禁止整卷通读）；
2. **先检索后探索**：开工先用 Memory（`operation=search`，projects/sessions 作用域）与 History 检索既有结论（函数名、踩坑、环境事实），命中即用；**检索预算 ≤3 次、单次 get ≤4000 字**，未命中不得换词循环重搜（按上下文包开工并向父会话提问）；探索范围限项目目录，禁止用盲 grep 替代检索；
3. **上下文包**（父会话填增量，不传会话流水）：任务背景一句话、已完成部分与账本位置、本次范围与验收、必须保持的契约、当前测试基线（哪些段已绿）、涉及 `文件:函数` 清单；
4. **环境事实**：直接内联或指向项目 `MEMORY.md` 的 Discovered 段（venv、服务端口/账号、MySQL/Redis 端口、Playwright 配置、PRE-EXISTING 基线名单）。
5. **效率预算（硬性 #15）**：轮次预算（单页 ≤40 / 总 ≤120）、重复禁令（同命令全绿后再跑 ≤1 次）、轮询退出判据、`timeout_ms` 硬顶；并把「已绿测试段清单」写进上下文包，防止重复验证。

### 父会话开工三步（派发/实施前，逐条可核对）

1. **先落清单**：页面级任务清单（每行：编号｜目标结果｜修改区域｜根因｜状态）写入 Task 工具与特性文档 §Tasks——清单是 brief 上下文包的账本来源，也是用户可核对的进度面；未建清单不得批量派发。
2. **盘点输入**：按 #13 查活跃代理；整理「已绿测试段清单」与涉及 `文件:函数`，写入上下文包。
3. **构造 brief**：按简报五件套组装，附 `timeout_ms`；同任务全局只允许一个活跃代理。

### 父会话监控

`status` 只在 **wait 超时/被中断后**各查 1 次（禁止为监控做短间隔主动轮询；确需巡检时间隔 ≥5 分钟、上限 6 次）——`turnCount` 超 150 必须介入（send 催收口或取消），子代理报告的「轮次/耗时」异常要复盘进特性文档 Journey。

## 验证纪律（硬性 #14）

1. **先清场后验证**：跑测试/截图前先查 `status`——无活跃写入者直接执行；有写入者才按 #13/预算纪律采样等待（间隔 5–10s、≤3 次，到顶→汇报阻塞）。写入窗口内跑出的失败（如一次性的 `css.index("th {")` 撞车、test_server 端口冲突 errors=18）必须复跑确认，禁止直接当真或当假。
2. **测试结果落盘**：`python -m unittest ... > run-logs/<域>-<时间戳>.log 2>&1` 后 grep 取数——输出被中断可读文件续查，不整段重跑。
3. **测试段上限 2 次**：同一测试段只允许首跑 + 1 次收口复跑（代码未变且首跑全绿），第 3 次禁止执行、引用之前的日志文件（与 #15 同口径）。**任一源码或测试文件变更后计数重置**。
4. **截图单轮矩阵**：验收类截图合并为一次全页面矩阵（唯一文件名、落盘到仓库内忽略目录、禁 rm）；发现缺陷→修码→**仅重拍受影响页**；每张截图落盘后立即校验（大小、md5 与同页历史文件不同；相同即无效→修导航/登录后新文件名重拍，同页最多重拍 1 次，仍无效→停手找根因）。

## 预算与监控（硬性 #15）

- **同命令计数**：子代理内对每条测试命令自行计数，全绿后再跑 ≤1 次收口；出现第 3 次同一命令 = 立即停止写报告（R2 实测：某代理同一条 `test_static_analysis` 每 9 秒重跑 23+ 次，输出从未变化——轮询无退出条件是 917 轮/68 分钟的头号原因）。
- **轮询模板**：任何「等到 X 稳定/就绪」必须写成 `for i in range(N): 采样; if 判据: break`——判据示例「mtime 两次一致」「端口可连」；到 N 仍未满足 → 汇报阻塞，不继续空转。
- **禁测试当 sleep**：等待窗口用一次 `sleep` + 判据，不用重跑测试填充轮次。
- **预算字段**：brief 写明单任务轮次上限；`spawn` 传 `timeout_ms`（单页 ≈30min、整批 ≤90min）。
- **父会话看门**：`turnCount > 150` 或预计超预算 → `send` 催「立即停止新增动作、输出当前结论报告」；再 10 轮未停则 `cancel` 并回收已完成增量。

## 汇报节奏（主会话与子代理均适用）

- **触发点与格式**：每次阶段转换（诊断→确认→清单→实施→验证→评审→收尾）输出一次进度表，格式固定为逐行「编号 | 状态 | 证据（测试 Ran N / 截图 N 张 / 文件:行）」；子代理完成报告必须含「测试命令与 Ran N」行。
- **收尾必报**：任务正常完成以【任务完成】+ 简报（做了什么/证据/产物）收尾；中断后续跑须注明中断点与续点——用户据此区分正常完成与意外终止。
- **长等待**：单次 `wait` ≤15 分钟、超时最多 2 次；之后改 `status` 轮询——**间隔 ≥5 分钟、上限 6 次**，到顶未完成→对子代理 send 催收口报告，轮询期间不新增其他动作。
- **预算告警**：turnCount 超预算或预估超时，先输出「当前进度 + 预计剩余」再继续，禁止静默执行到超时。

## 执行效率与取证纪律（硬性 #16 / P1–P7）

适用：一切开发/测试/研究动作。目标：**完成任务前提下最小化 token 与往返**；验证强度不降（红绿、L0–L2 分段、全量对账原样保留）。本节是对既有条款的执行模板细化，非替代。

> **落盘路径**：本环境的 `/tmp` 会被周期清空（实测：日志文件在一次命令内消失），
> 且 `nohup` 后台进程活不过单次 shell 调用。**一律落仓库内已 gitignore 的目录
> （当前 `run-logs/` 与 `perf-logs/`）**，且起服务 + 压测须在同一条命令内完成。

1. **等待协议（P1）**：>30s 的任务（测试、服务、批量脚本、截图矩阵）一律 `nohup <cmd> > run-logs/<域>-<时间戳>.log 2>&1 &` 后台执行，回报 `PID=… LOG=…`（写路径前先 `sleep 1; ls` 确认文件已建，防 nohup 竞态漏文件）。等待只允许两种：①带退出判据的短轮询 `for i in $(seq 1 N): <判据> && break; sleep 5`——**前台单次阻塞 ≤20s**，循环总长写明上限，到顶→汇报阻塞；②工具自带 `wait`（≤15min×2 次上限）。**禁止整段前台 `sleep` 长阻塞**（实测教训：`sleep 100` 被用户中止并追问，浪费一轮往返）。脚本内部自带的长等待同样适用——把脚本本身 nohup 化，会话只轮询判据。
2. **测试取证双产出（P2）**：测试类命令统一 `python -m unittest … > run-logs/<段>-<时间戳>.log 2>&1; grep -E '^(OK|FAILED|Ran |ERROR: |FAIL: )' <log>`——落盘与取数同一动作：中断可续查、防止「结果只活在对话里→被迫重跑」。预期输出 ≤20 行的短命令（`git status`、单点查询）可直出不落盘，避免为落盘而落盘的仪式浪费。
3. **编辑三拍（P3，扩充 #12 工具口径）**：改任何文件前先 Read 精确定位目标行；`old_string` **逐字复制自 Read 输出**——优先取 ≤3 行小锚点；确需大段（整函数替换）时必须整段来自 Read 输出，**禁止凭记忆手打转录**。Edit 失败 1 次→立即换更小锚点/更近上下文，而不是改措辞原样重试（实测教训：手打大段致 3 次匹配失败 + 1 次参数格式错误，5 次往返纯浪费）。工具失败计数并入 #12：同工具 2 败即换法。
4. **先验证后落笔（P4）**：写脚本/一次性实验前，先用 `python -c '<最小片段>'` 验证语法要点（f-string 嵌套、属性存在性等）再写入文件。红绿验证保留：红跑只配 1–2 条最小断言（能证明红即可），避免整脚本多轮全量重跑；红→改码→绿属「代码变更重置计数」，不占 2 次上限。
5. **研究预算（P5）**：研究/排查开工先列 ≤3 个必答问题，每问 ≤2 次工具（`grep -n`/codegraph 定位行号 → **小窗** Read）。codegraph/搜索一次性返回大段源码视为超阈——下一次改符号级 query 或缩窄条件。豁免：根因已定位后读完整函数/文件不受限；Memory/History 检索另按简报五件套 ≤3 次（与本条独立计数，勿混算）。
6. **纠正即入库（P6）**：用户对行为/格式/流程的每次纠正，**当轮**写入项目 `MEMORY.md` Rules（跨项目级→global MEMORY），下轮立即生效——一次纠正只付一次成本，同类问题被纠正两次即视为违规。
7. **收尾与进度（P7）**：重大阶段转换输出「编号 | 状态 | 证据」进度表（与「汇报节奏」合并执行，不另起格式）；任务正常完成必须以**【任务完成】+ 简报**（做了什么/证据/产物）收尾，中断后续跑注明中断点与续点。

**与既有条款的冲突自检**（防误读/机械执行）：P1 是 #14/#15 轮询的通用化，二者并存；P2 即 #14 落盘模板；P3 是 #12 工具口径细化（2 败换法不变，1 败即换锚点更严）；P4 红绿受 #14 计数约束（代码变更重置）；P5 与简报五件套检索预算分属「探索/记忆」两域独立计数；P7 与「汇报节奏」为同一动作的两处引用，输出一次即可；P1 例外仅限 ≤20 行短命令直出与工具自带 wait 上限。
