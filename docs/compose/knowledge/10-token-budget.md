# Token 预算与上下文经济学（硬性 #20）

> 对应硬性约束 #20。**只在两种时候读本卷**：① 会话收尾自查 / 复盘；② 准备做长任务、
> 大批量检索或读大文件之前。日常只需记住 AGENTS.md #20 的那几句。
> 数据来源：`~/.dsh/sessions/` 记录里的真实 `usage`（2026-10-06 实测，4 个会话）。

## 一句话版

1. **成本 ≈ 步数 × 上下文规模**——实测 4 个会话 Σtotal 69.7M tokens，其中 **98.6% 是历史重发**（cacheRead），
   模型输出只占 **0.58%**。省 token 的唯一主战场是「上下文 × 步数」，不是「让模型少说话」。
2. **一步塞进历史的东西，后面每一步都要重发一次**：第 k 步新增 A tokens，全程就要多付 `A × (总步数 − k)`。
   所以「早几步塞的大返回」比「晚几步塞的」贵一个数量级。
   （2026-10-09 实测：全项目 **38 个会话累计 730,125,694 tokens**，见 `session_cost.py --all`）
3. **单条工具返回 >8k 字符即超阈**：先计数（`grep -c`）、再截断（`head`）、再读（`read offset/limit`）。
4. **互不依赖的调用同步发**（一步 2–4 个）——每省掉一步就省「该步上下文 + 1.6 万固定开销」。
5. **长会话要分段**：>60 步或上下文 >120k tokens → 落盘 HANDOFF，换新会话续做。

## 一、实测账本（2026-10-06 复盘，4 个会话）

| 会话 | 步数 | Σtotal tokens | 首步上下文 | 末步上下文 | 平均/步 | 重发占比 |
|------|------|---------------|-----------|-----------|---------|---------|
| API 端点展开收起失效 | 147 | 23,980,841 | 18,813 | 260,638 | 163,134 | 98% |
| 检查并修复 V2 知识库文档 | 103 | 20,086,406 | 16,508 | 300,598 | 195,013 | 98% |
| 梳理项目未完成任务清单 | 96 | 16,382,252 | 20,346 | 270,393 | 170,648 | 98% |
| Git 分支 V1/V2 版本管理方案 | 94 | 9,216,957 | 16,609 | 161,600 | 98,052 | 98% |
| **合计** | **440** | **69,666,456** | — | — | — | **98.6%** |

拆开看：cacheRead 68,670,592（98.6%）· input 594,330（0.85%）· output 401,534（**0.58%**）。

**推论 1：单步固定开销 ≈ 1.6 万 tokens。** system 提示 10.3k 字符 + 工具 schema 29.6k 字符 +
AGENTS.md 15.6k 字符 + 技能目录 6.7k 字符 ≈ 63k 字符，每个 step 都要重发一次（实测会话 1 首步 = 18,813 tokens）。
440 步 × ~1.6 万 ≈ **700 万 tokens 只花在「存在」上**。

**推论 2：长会话是二次成本。** 上下文单调增长，Σ ≈ 步数 × 末尾上下文 ÷ 2。
会话 1 用 147 步把 18.8k 撑到 260.6k → 2400 万 tokens。同样的活拆成 3 段各 ~50 步，
每段从 ~19k 重新起步，总量可降到约一半。

### 最贵的步（重发成本 = 该步新增 × 剩余步数）

| 会话·步 | 干了什么 | 该步新增 | 重发成本 | 占该会话 |
|---------|----------|---------|---------|---------|
| 1 · 第 4 步 | 全库 `grep "api-endpoints"` 225 命中（43k 字符）+ `cat test_env.sh` | 16,274 | **2,327,182** | 9.7% |
| 3 · 第 5 步 | 两条 bash 未收窄输出 | 24,051 | **2,188,641** | 13.4% |
| 2 · 第 6 步 | 一次 `read` 4 份整卷知识库文档 | 21,085 | **2,045,245** | 10.2% |
| 1 · 第 60 步 | `edit` 大测试文件（回显全文 hashline） | 19,853 | 1,727,211 | 7.2% |
| 2 · 第 7 步 | 再读 2 份整卷文档 | 16,537 | 1,587,552 | 7.9% |
| 1 · 第 61 步 | 两条 bash | 18,244 | 1,568,984 | 6.5% |
| 2 · 第 3 步 | 两条 bash | 12,249 | 1,224,900 | 6.1% |

**前 3 步就吃掉单会话的 10%–23%**——全部发生在开工探索期。开工前 10 步的返回体积，
基本决定了这一场的总账单。

### 2026-10-09 第二批实测（本仓最近 2 个会话：mermaid 渲染 + 报表编辑页）

| 会话 | 步数 | Σtotal tokens | 末步上下文 | 单调用步 | 重发占比 | AOCI maintain 调用 |
|------|------|---------------|-----------|---------|---------|-------------------|
| mermaid 渲染修复 | 147 | 23,982,676 | 282,563 | **113（76%）** | 96% | 2 次（违规） |
| 报表编辑页修复 | 149 | 23,197,779 | 292,970 | **110（73%）** | 98% | 3 次（违规） |

- **结论 1：批处理纪律没有改善**——2026-10-06 实测会话 1 是 80% 单调用步，本轮两场 76%/73%，等于「没有触发」
  （#20② 在上一次复盘中已写明，仍未被当纪律执行）。所以 R2 必须给**可核对阈值**与**工具输出**，不能只写形容词。
- **结论 2：会话长度是主乘数**——两场都跑到 60 步上限的 2.5 倍；`Σ ≈ 步数 × 平均上下文`。
  同样工作拆成 3 段各 ~50 步（每段从 ~20k 重新起步）估算约 9–11M tokens，**可省一半以上**。
- **结论 3：AOCI 中间态重复调用**——两场分别在收尾前、收尾各调 maintain（2 次 / 3 次，同参数 `{}`），
  前几轮被后一轮完全取代；单次返回 8.6–14.2KB。规则 #21 早已禁止「中间态/重复调」，但没有机械拦阻。
- **结论 4：收尾尾巴很贵**——第 1 场最后 28 步（#120–147）= 该会话 **30.7%** tokens，其中 17 步是 AOCI；
  收尾项「一项一步」是主因 → R5 改为**一次批量发**。

## 二、硬规则（可核对）

### R1 单条工具返回 >8k 字符即超阈

判定用 `scripts/agent/session_cost.py`（超阈步会直接列出来）。收窄命令表：

| 场景 | 禁止 | 改用 |
|------|------|------|
| 找符号 / 调用链 / 影响面 | `grep -rn` 全库 | `codegraph explore "<中文+代码词>"`（#18，一次顶一轮循环） |
| 不知道命中规模 | 直接全库 grep | `grep -rc "词" --include='*.py' .` 先计数，>40 就先缩条件 |
| 找文案 / CSS 类名 | 全库 grep 出 200 行 | `grep -rn -m 5 "字面量" --include='*.py' .` 或 `... \| head -40` |
| 读文件 | 无 `limit` 整读 | `grep -n "关键字" f` 定位 → `read f offset=N limit=40` |
| 大文件结构 | 整读 `render.py` | `codegraph node --file render.py --symbols-only` |
| 跑测试 | `-v` 直出全量 | `… > run-logs/<段>-<时间戳>.log 2>&1; grep -E '^(OK\|FAILED\|Ran )' <log>`（#16 P2） |
| 看日志 | `cat run.log`（33KB+） | `grep -n "ERROR\|Traceback" run.log \| tail -20` |
| 后台作业 | 整段 `job_output`（本仓实测单次 49,932 字符） | `… > run-logs/<名>.log 2>&1` 落盘 → `grep`/`tail` 只取判据行 |
| 列目录 | `ls -R` | `ls dir \| head -30` |
| git 历史 | `git log -p` | `git log --oneline -10`；单文件 `git log --oneline -5 -- f` |

### R2 互不依赖的调用同步发

一步发 2–4 个互不依赖的 `read`/`grep`/`bash`/`codegraph`。反例：会话 1 有 118 步只发了 1 个调用；
2026-10-09 两场仍有 113/147（76%）与 110/149（73%）是单调用步。
- **可核对阈值：单调用步 ≤40%**——`session_cost.py` 报告的「批处理率」一行直接给出，`--check` 也会判。
- **中途体检**：完成首个交付物后、开始收尾前各跑一次
  `venv/bin/python scripts/agent/session_cost.py --check`（只输出一行，约 60 字符，可随时跑）。
- 允许：`read A` + `read B` + `grep -n C` 同一步；
- 不允许：为了「看清楚再决定」而一步一问地碎步推进（每步 1.6 万固定 + 全量历史）。
- 有依赖时必须串行——别为了凑批处理把后一步的参数猜出来。

### R3 长会话分段（>60 步 或 上下文 >120k tokens）

**触发时机（事件触发，别靠自觉记步数）**：完成首个可交付结果后、开始收尾前，各跑一次
`session_cost.py --check`（只输出一行）；只要出现「必须落盘交接并换会话」，或任何一次全量测试前发现
>60 步 / 上下文 >120k，就**停下写交接**，让用户开新会话（或在同仓新会话继续），交接文件放
`docs/compose/reports/handoff-<YYYY-MM-DD>-<主题>.md`（长期依据，随任务提交；唯一文件名）：

```markdown
# 交接：<主题>
> 时间 / 对应 spec / 上一会话 id

## 1 目标与验收（一句话 + 判据命令）
## 2 已完成（文件:行 + 证据：测试 Ran N / 数据）
## 3 未完成 / 下一步（可直接粘贴执行的第一条命令）
## 4 关键事实（端口、账号、契约、测试基线哪些段已绿）
## 5 不要重做（已排除的假设、已跑过的命令与结论）
```

新会话开工只读这份交接 + 相关分卷章节，**不要**让新会话重读整个仓库——
这正是把 260k 上下文换成 5k 文档的地方。

### R4 大文件写入集中到会话后段

`write`/`edit` 的返回会**回显改动后的文件内容（hashline 全文）**，直接进上下文。
`render.py`(334KB) / `config.py`(143KB) / `report.py`(100KB) 这类文件：
- 一次批量改完（`edits` 数组带多个锚点），不要「改一处 → 跑一遍 → 再改一处」；
- 尽量放在会话后段（剩余步数少 → 重发次数少）；
- 只读检查用 `read offset/limit`，不要为了让工具「给锚点」而整读。

### R5 收尾自查

venv/bin/python scripts/agent/session_cost.py --last 1     # 本会话完整报告（超标逐条列出）
venv/bin/python scripts/agent/session_cost.py --check      # 一行体检（中途与收尾都跑它）
venv/bin/python scripts/agent/session_cost.py --all        # 本项目全部会话汇总
venv/bin/python scripts/agent/session_cost.py --selftest   # 工具自测
```

超标不必道歉，但要**在收尾简报里报数字**，并把可复用教训写进 `MEMORY.md`（#16 P6）。

**收尾取证一次批量发**：把「测试 + `codegraph status` + `git diff --stat` + `--check`」串成**一条** `bash`
（日志落 `run-logs/` 后 `grep` 判据行），末行追加 `venv/bin/python scripts/agent/cleanup_tmp.py --apply` 统一清理临时产物（**0 额外轮次**），禁止一项一步——实测第 1 场收尾 28 步占了该会话 30.7% tokens。

## 三、反向结论：别在 output 上抠门

output 只占 0.58%。所以：

- **推理、写 TODO、写清问题定义极便宜**——该想清楚就想清楚，该问就问（`ask_user_question` 几百 tokens，
  远低于一次错误实现）。
- 反过来，为「省字」而含糊其辞、猜测用户意图、少写验收标准，会导致返工——返工至少多 10 步 = 16 万 tokens 起。
- 真正昂贵的是**把大段内容灌进历史**：大返回、整卷文档、全库 grep、大文件回显。
